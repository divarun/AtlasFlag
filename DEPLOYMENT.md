# Deployment Guide

AtlasFlag's Spring Boot service serves both the web dashboard and the REST API from a single process. You can run everything on Render alone — no separate frontend hosting required.

> **Cold start warning:** Render's free tier spins the service down after 15 minutes of inactivity. The next request takes ~30 seconds to wake up. Upgrade to Render's $7/month Starter plan to eliminate this.

---

## Render + Neon (recommended)

Everything runs on one Render web service. The Spring Boot app serves the dashboard at `/dashboard` and the API at `/api/v1/...` from the same URL.

### Step 1 — Database (Neon)

1. Go to [neon.tech](https://neon.tech) and create a free account
2. Create a new project — name it `atlasflag`
3. On the Dashboard, find **Connection string** and select **JDBC** format:
   ```
   jdbc:postgresql://ep-xxx-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
4. Note the JDBC URL, username, and password — you'll need them in the next step

### Step 2 — Render web service

1. Push your code to GitHub
2. Go to [render.com](https://render.com) → **New → Web Service**
3. Connect your GitHub account and select this repository
4. Render detects `render.yaml` automatically — click **Apply**
5. Set these environment variables (marked `sync: false` in `render.yaml`):

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Your Neon JDBC URL |
   | `DATABASE_USERNAME` | Your Neon username |
   | `DATABASE_PASSWORD` | Your Neon password |

   `JWT_SECRET` is auto-generated by Render (`generateValue: true`).  
   `CORS_ALLOWED_ORIGINS` — leave blank (not needed for same-origin dashboard access).

6. Click **Create Web Service** — first build takes ~3–5 minutes

### Step 3 — Access

Once deployed, your service URL looks like `https://atlasflag-backend.onrender.com`.

| Page | URL |
|---|---|
| Dashboard | `https://atlasflag-backend.onrender.com/dashboard` |
| Login | `https://atlasflag-backend.onrender.com/login` |
| Health check | `https://atlasflag-backend.onrender.com/actuator/health` |

Log in with `admin` / `admin123` and change the password immediately.

### Verify it works

```bash
# Health check
curl https://atlasflag-backend.onrender.com/actuator/health
# {"status":"UP"}

# Login
curl -X POST https://atlasflag-backend.onrender.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# {"token":"eyJ...","username":"admin","role":"ADMIN"}
```

## Manual Render setup (without render.yaml)

If you prefer to configure the Render service by hand instead of using `render.yaml`:

| Field | Value |
|---|---|
| Runtime | **Docker** |
| Dockerfile Path | `./Dockerfile` (auto-detected) |
| Health Check Path | `/actuator/health` |

Environment variables to add manually:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon JDBC URL |
| `DATABASE_USERNAME` | Neon username |
| `DATABASE_PASSWORD` | Neon password |
| `JWT_SECRET` | Random string, min 32 characters |

`PORT` and `JAVA_OPTS` are set inside the Dockerfile — you don't need to add them manually.

---

## Environment variables reference

| Variable | Required | Default | Description |
|---|---|---|---|
| `DATABASE_URL` | Yes | `jdbc:postgresql://localhost:5432/atlasflag` | PostgreSQL JDBC URL |
| `DATABASE_USERNAME` | Yes | `atlasflag` | DB username |
| `DATABASE_PASSWORD` | Yes | `atlasflag` | DB password |
| `JWT_SECRET` | Yes in prod | dev default | Min 32 chars — auto-generated by Render |
| `CORS_ALLOWED_ORIGINS` | Only for Option B | localhost | Comma-separated allowed origins for cross-origin SDK/frontend access |
| `PORT` | No | `8080` | HTTP port — Render injects this automatically |
| `DB_POOL_SIZE` | No | `5` | HikariCP max connections — keep low on Neon free tier |
| `DB_SSL_MODE` | No | `prefer` | Set to `require` for Neon and most cloud Postgres providers |

## Troubleshooting

**Build fails on Render**
- Ensure `JAVA_VERSION=21` is set in Render's environment
- The first build downloads all Gradle dependencies — ~3 minutes is normal
- Check Render build logs for the specific Gradle error

**`Connection refused` to database**
- `DATABASE_URL` must start with `jdbc:postgresql://` (not `postgres://`)
- Neon URLs must include `?sslmode=require`
- Confirm username/password are copied from the Neon dashboard (not the connection string — those are URL-encoded)

**Dashboard loads but API calls fail (Option B only)**
- Verify `CORS_ALLOWED_ORIGINS` exactly matches your Vercel URL: `https://atlasflag-xxx.vercel.app` — no trailing slash
- Confirm Render redeployed after you set the env var (check the Render dashboard)
- Check browser DevTools → Network → look at the failed request's response headers for the CORS error

**Cold start / slow first request**
- Expected on Render free tier after 15 min idle
- The first request after a cold start takes 20–30 seconds
- Upgrade to Render Starter ($7/month) to eliminate this

**Login redirects back to login page**
- JWT_SECRET must be at least 32 characters — if Render generated it, it will be fine
- Check that `localStorage` is not blocked in your browser (private mode sometimes blocks it)
